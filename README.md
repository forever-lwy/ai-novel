# AI Novel

私有部署的 AI 小说创作工作台。导入已有小说，或从一个设定开始，持续维护正文、角色、世界观、剧情、大纲与伏笔。

## 项目方向

- **写小说**：从创意、世界观和角色设定出发，编写大纲与正文。
- **写同人**：基于已有作品的人物和世界观，创作新的故事。
- **改写小说**：按照指定要求调整情节、视角或表达，保留原文供对照。
- **穿入小说**：扮演故事中的角色，通过选择和行动参与剧情。

## 运行

需要 Node.js 24 或更新版本。

```sh
npm ci
npm run dev
```

浏览器打开 http://localhost:5173，首次使用设置个人密码（至少 8 位）。开发服务默认只监听本机，网页通过代理访问 4317 端口的 API。

生产运行：

```sh
npm run build
npm start
```

打开 http://localhost:4317。可复制 `.env.example` 为 `.env` 调整端口、数据目录等；默认数据库和上传文件放在 `data/`，不进入 Git。

## Docker / NAS

```sh
docker compose up -d --build
```

默认绑定主机 `127.0.0.1:4317`。先在受信任环境完成首次密码设置，再开放访问。局域网访问可在 `.env` 设置 `BIND_ADDRESS=0.0.0.0`；跨互联网使用时通过反向代理提供 HTTPS，并设置 `PUBLIC_ORIGIN=https://你的域名` 和 `COOKIE_SECURE=true`。

应用使用单实例和 SQLite；持久化卷必须位于服务主机的本地存储，不要将运行中的数据库放在 SMB/NFS 共享目录。数据库、原文及加密密钥均在持久化卷内，升级容器不会主动清空。

## 使用顺序

1. 新建作品，在“供应商设置”添加服务地址、协议和密钥，再为正文写作、大纲规划、资料提取分别选择供应商与模型。选择供应商后会自动获取上游模型列表，也可以直接填写自定义模型名。
2. 原创可输入设定、生成大纲后开始写作；导入作品上传 TXT／EPUB，检查分章，再开始整理。
3. 每次生成一章或选定片段；完成后自动保存正文并整理资料。整理期间等待完成；失败后在任务页重试，不需要重新生成正文。
4. 世界资料使用等高卡片，点击条目或“查看详情”展开完整描述、事实与出处，可纠正资料或合并别名。地点关系图只展示地理地点、区域与连接；人物当前位置单独显示。
5. 从章节结尾建立分支。修改较早章节会自动另开修订线，回退版本会同时恢复正文和资料。

阅读模式默认不返回内部大纲、伏笔答案、秘密资料或未来事实；“查看作者资料”显式进入作者视图。作者可以人工修改、锁定资料。AI 提取仍可能遗漏或误判，应通过出处核对，程序校验不能替代语义判断。

导入与正文整理会同时提取已发生的剧情摘要，在“大纲与伏笔 → 故事大纲”按章展示，供续写参考。摘要与未来粗纲、细纲分开保存。伏笔手记默认只显示尚未揭晓的线索，已揭晓与已放弃条目可通过历史入口查看，并从后续提取、规划和写作的待处理伏笔中移除。人物的位置按最新明确到达记录更新；回忆、目的地和未来计划不会覆盖当前位置，回退或从旧章节分支时恢复当时的摘要、伏笔及位置。

## 模型服务

| 协议 | API 前缀示例 |
| --- | --- |
| OpenAI Chat Completions | `https://api.openai.com/v1` |
| OpenAI Responses | `https://api.openai.com/v1` |
| Google Gemini | `https://generativelanguage.googleapis.com/v1beta` |
| Claude Messages | `https://api.anthropic.com/v1` |

填写 API **前缀**，程序仅追加所选协议的相对路径，不自动补 `/v1`。兼容网关可以填写自定义前缀。Chat 协议使用通用 `max_tokens` 字段；需要 OpenAI 推理模型的专有输出控制时选择 Responses。

供应商连接保存协议、地址和密钥。同一个供应商可供三个任务使用不同模型；生成参数、输出上限和上下文上限在任务模型选择下方设置，按“任务用途＋供应商＋模型名称”分别保存。正文写作、大纲规划、资料提取即使使用同一供应商的同一模型，也各自保存参数；在同一任务中切换模型后再选回会恢复原设置。模型列表按当前供应商草稿查询，无需先保存；列表不可用或网关没有列出所需别名时，仍可填写自定义模型名。切换任务供应商后需重新选择或填写模型，程序不会替你选择列表中的第一项。旧版连接中的模型名和生成参数会转入原任务使用的模型；旧版跨任务共用的模型参数会分别复制给各任务，密钥继续保留。

密钥在服务端加密保存，页面只返回“已保存”状态。连接测试会发起一次真实模型请求；失败不自动重试。完整作品备份不包含服务密钥、登录密码或会话。

### 生成参数与思考设置

选择模型后可展开“生成参数与思考设置”。新模型的通用默认值为温度 `1`、Top P `1`、存在与频率惩罚 `0`、单次最大输出 `4096` tokens、上下文上限 `64000` tokens、超时 `180` 秒、非流式；可一键恢复这些默认值。思考模式、随机种子、Top K 和停止序列默认不发送。已有模型的设置保持原值，主动清空的可选参数不会在保存后重新补值。不同型号支持范围不同，服务不支持的可选项可清空。

上下文上限限制每次请求的预估输入与完整预留输出之和；单次输出按该模型保存的上限发送，不因历史用量缩小。可选项留空表示不发送，数字 `0` 会保留。温度、Top P、Top K、停止序列、随机种子及重复惩罚按协议显示和发送。

- OpenAI Chat / Responses：设置思考等级；Chat 可选择 `max_tokens` 或 `max_completion_tokens`，只发送选定的一种。
- Gemini：选择思考等级或 token 预算，二者互斥；另可选择是否返回思考摘要（`includeThoughts`），摘要不会进入正文或提取结果。具体范围取决于模型；Gemini 3 系列优先使用等级，并先保留服务默认的采样参数。
- Claude：思考支持服务默认、关闭、手动预算、自适应，另可设置 effort。手动预算至少 1024，且小于保存的单次输出上限；开启思考时的采样限制由界面和服务端检查。
- 返回方式可选非流式或流式。流式持续接收事件，完整后校验入库；接收中断会保留已收到的部分。流式不能保证绕过网关自己的请求时限。
- 超时可设为 1–3600 秒，留空为 180 秒。实际发送参数可在请求诊断中查看。

任务配置中的“保存并测试连接”使用该任务选择的供应商与模型，按当前参数和输出上限发送一次短提示词请求，成功和失败均展示本次诊断。不同模型和网关支持的参数不同；程序不会为了重试而自行替换模型或参数。自动获取模型列表不发送生成请求。

导入按章节和片段整理，不把全书反复发给模型。任务累计输入与输出仅作用量统计，不再设置累计限额；旧设置中的任务用量上限会被忽略并在保存时移除。单次请求的预估输入与完整预留输出超出上下文上限时，会在请求发送前停止并保留进度，调整上下文上限或减少本次输入后可手动重试。服务重启后运行中的任务转为暂停，需要手动恢复；模型调用过程中断的请求可能已由供应商计费，重试可能再次产生用量。

如果任务提示“模型服务请求失败（HTTP 500）”，表示模型接口返回了错误，具体原因需要结合服务商状态或配置判断。可先用“保存并测试连接”检查连接；恢复后在原任务上点击“重试”，不需要重复上传小说。“取消任务”会停止后续处理，已经保存的原文和资料仍保留。

对比“测试场成功、任务失败”时，进入作者任务的“模型输出 / 手工修正 → 实际请求与连接诊断”，核对 URL、协议、模型、流式开关、温度/思考、最终输出上限、耗时与响应头。请求在发送前留存，空响应、连接失败和超时也有记录；旧记录没有快照时会明确说明。密钥已脱敏，但请求正文含作者素材，下载后应按作品资料保管。

诊断还会显示模型结束原因及输入拦截原因，区分已返回正文、模型拦截、输出截断、成功但没有正文和服务错误。网关只有 500／502 错误包、没有返回模型反馈时，不推断为引用错误或内容拦截；需要核对网关的实际出站响应。已收到的原响应仍保留，未收到的正文不能恢复。

AxonHub 的渠道测试场是管理接口，可直接指定渠道；普通 API 使用自己的模型映射和路由，不能仅按提示词相同认定等价。排查步骤和源码依据见 [模型连接排查](docs/MODEL-CONNECTIONS.md)。不要把浏览器 Cookie 或 Cloudflare 登录凭据复制进模型配置。

### 校验失败时手工修正

在**作者视图 → 任务 → 模型输出 / 手工修正**中，可以查看每次响应、最初的模型文本、具体错误字段及对应原文。模型响应会先保存，再检查 JSON、字段和引用；未通过校验的内容不会直接写进世界资料。

- 默认使用可视化表单，直接修改摘要、人物或地点、事实、关系及伏笔，不需要了解 JSON。点击问题旁的定位入口，找到对应字段。
- 引用不符时，先核对这条事实是否正确，再选择支持它的原文段落；可以直接使用该段，也可以在段落中选取一段文字作为引文。没有原文依据的条目应删除或改正，不能只换一段无关文字让它通过。
- 关系名称应选择已识别的资料名称或别名；“过去”用于回忆，“当前”用于此时发生的状态，无法确认时选“不明确”。秘密与未来安排不要标成公开事实。
- “高级 JSON”保留完整结构编辑。语法损坏、无法显示表单时，可在这里修复格式，再返回可视化编辑；没有收到的内容不会由程序猜测补齐。
- 原始响应只读保存，修正另存；即使修正后仍失败，提交的修改也会保留。
- 点击“保存并校验应用”只做本地处理，不调用模型，也不增加模型用量。通过后，任务完成或保持暂停；需要处理后续片段时再点击“继续”。
- “重试”会重新调用模型，与手工修正不同。
- 旧任务没有自动留存记录时，使用“粘贴历史响应”导入已有结果；支持完整 Gemini、OpenAI、Claude 响应及直接输出的 JSON / 正文。
- 已取消、已完成、进度已变化或故事线版本不匹配的输出仍可查看和下载，不能覆盖当前故事。

输出仅在作者视图开放，已知密钥及响应中的凭据字段会脱敏。收到的响应限制为 16 MiB；超限、截断或网络中断时保留已收到的部分并标记不完整。连接失败且服务没有返回任何内容时，没有可保存的模型输出。

新提取流程让模型提供段落编号，由程序从当前片段取回精确原文，不再要求模型逐字重抄引文。旧响应仅有空白或引号差异、且能唯一定位时，会自动对齐并记录说明；错字、无法定位或有歧义的引用仍需修正。省略的可选字段采用保守默认值，未来大纲不混入提取上下文。详细规则与 AiNiee 参考记录见 [提取流程说明](docs/EXTRACTION.md)。

## 数据与备份

- 作品备份为 `.ai-novel.json.gz`，包含原文件、章节、各故事线、历史资料、模型输出及手工修正、未完成任务的进度，恢复时建立独立作品。旧版 JSON 备份也可读取；恢复的运行中任务转为暂停，手动继续后接着整理。
- 正文可以单独导出 TXT。作品备份包含作者秘密，请按私人创作资料保管。
- 迁移整个服务时，停止服务后备份整个数据目录或 Docker 卷，尤其保留 `.encryption-key`；该文件用于解密模型密钥。
- TXT 支持 UTF-8、UTF-16 和 GB18030；EPUB 按阅读顺序提取正文，不加载外部资源，不处理 DRM。上传小说最大 32 MiB，解压后最多 128 MiB，正文最多 2000 万字。
- 作品备份上传最大 128 MiB，外层解压最大 512 MiB，单个历史世界状态解压最大 64 MiB；长期积累超出单作品备份范围时使用完整服务目录备份，不删除或截断历史。

## 开发与验证

```sh
npm run typecheck
npm test
npm run build
npm run test:e2e
```

`client/` 为 React 网页，`server/` 为 Fastify、SQLite、模型与任务逻辑，`shared/` 为共同类型，`tests/` 为协议和业务验证。接口见 [API-CONTRACT.md](docs/API-CONTRACT.md)，实现边界与验收记录见 [VALIDATION.md](docs/VALIDATION.md)。

浏览器测试默认使用系统 Microsoft Edge，测试服务使用独立临时目录和本地模拟模型，不调用真实供应商。没有 Edge 的机器可以安装 Edge，或自行调整 Playwright 的浏览器配置；这不影响正常使用网页应用。

当前阶段实现文字创作；绘图、RPG、多人协作、公开发布和离线同步尚未实现。模型协议模拟测试不等于真实模型效果验证，具体以验收记录为准。
