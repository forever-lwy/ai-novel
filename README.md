# AI Novel

私有部署的 AI 小说创作工作台。支持原创、续写、同人和改写，导入已有小说或从设定开始，持续维护正文、人物、世界观、剧情摘要、预期规划与伏笔。

## 可以做什么

- 导入 TXT／EPUB，确认分章后逐段整理资料；原创可以直接开始写作。
- 流式生成正文，生成草稿自动保存并可在刷新后恢复查看；正文先保存，资料在后台独立整理。
- 编辑正文、改写整章或选段、重新生成章节；建立分支、修订和回退，同时恢复正文与故事资料。
- 查看人物与世界资料、原文出处、地点关系图、剧情摘要和伏笔，人工纠正、锁定或合并资料。
- 自动绘制新人物立绘，为人物、各类实体与地图生成图片；按章节或选段生成剧情 CG，在图册启用、停用、删除、重新绘制和用 AI 修改，支持图片缩放与全屏查看。
- 为不同任务选择供应商和模型，编辑提示词预设、消息块与变量；查看实际请求诊断和作者生成过程。
- 导出正文、备份与恢复完整作品，或确认后删除作品及相关数据。

当前采用单用户、单实例部署。完整能力、未实现方向与验证边界见 [项目状态](PROJECT-STATUS.md)；详细操作见 [使用指南](docs/USAGE.md)。

## 快速运行

需要 **Node.js 24 或更新版本**。

### 本地开发

```sh
npm ci
npm run dev
```

打开 [开发工作台](http://127.0.0.1:5173)。首次使用设置个人密码，至少 8 位。网页和 API 默认只监听本机，Vite 将 `/api/` 请求代理到 `127.0.0.1:4317`。

### 生产运行

```sh
npm ci
npm run build
npm start
```

打开 [工作台](http://127.0.0.1:4317)。服务同时提供 API 和构建后的网页，不需要另外运行 Vite。

默认无需创建配置文件；需要调整时，复制 [.env.example](.env.example) 为 `.env`，服务启动时会自动读取。

| 配置项 | 默认值与用途 |
| --- | --- |
| `HOST` | `127.0.0.1`，服务监听地址 |
| `PORT` | `4317`，API 与生产网页端口 |
| `DATA_DIR` | `./data`，数据库、原文件及加密密钥目录 |
| `PUBLIC_ORIGIN` | 外部访问来源，例如 `https://novel.example.com` |
| `COOKIE_SECURE` | 未设置时为 false；通过 HTTPS 访问时设为 `true` |

开发时若更改 API 的 `PORT`，还需同步调整 [vite.config.ts](vite.config.ts) 中的代理目标。生产运行不使用开发代理。

### Docker／NAS

```sh
docker compose up -d --build
```

[Compose](compose.yaml) 默认绑定主机 `127.0.0.1:4317`，数据持久化到 `novel-data` 卷的 `/app/data`。先在受信任环境完成首次密码设置；局域网开放可在 `.env` 设置 `BIND_ADDRESS=0.0.0.0`，该项用于 Compose 的主机端口绑定。

通过互联网访问时，使用反向代理提供 HTTPS，并设置 `PUBLIC_ORIGIN=https://你的域名` 和 `COOKIE_SECURE=true`。SQLite 数据必须放在服务主机本地存储，不要将运行中的数据库放在 SMB／NFS 共享目录。Docker 与目标 NAS 的实机验收情况见 [项目状态](PROJECT-STATUS.md#当前限制与未验证部分)。

## 开始创作

1. 新建作品，打开“设置”。在“供应商连接”填写 API 前缀、协议和密钥，再在“任务模型”为正文写作、剧情规划、资料提取选择模型；模型列表不可用时可手动填写模型名。
2. 原创填写设定后直接写作，无需预先规划。已有作品上传 TXT／EPUB，检查分章后开始整理。
3. 发起生成后实时查看正文。正文完成先保存，再整理资料；继续下一章前需完成上一章资料整理。资料失败时只重试整理，也可在作者任务页手工修正。
4. 需要不同走向时建立故事线；改写或重新生成会保留原线。阅读视图过滤秘密与未来内容，切换作者视图后可查看和调整资料。

供应商连接与任务模型分别保存；参数按“任务用途＋供应商＋模型”独立保存。支持 OpenAI Chat Completions、OpenAI Responses、Google Gemini 和 Claude Messages；填写 API **前缀**，程序不会自动补 `/v1`。具体配置与参数规则见 [使用指南](docs/USAGE.md#模型服务)。

“提示词编排”支持正文、规划、提取和摘要压缩四个任务，多份预设、消息块、变量、模式条件与编译预览。预览不调用模型；连接测试会发起一次真实请求。单次上下文超限会在请求前停止，不因历史用量缩小输出上限，不隐式重试可能计费的生成请求。

“生图与自动插画”复用供应商连接，支持 OpenAI 兼容 Images、Gemini 和 Together。绘图前先由文字 AI 根据资料、剧情和要求编写专用生图提示词；可独立选择优化模型，默认使用规划或写作模型。CG 在模型支持时发送出场人物的已有立绘作为参考，尺寸、画幅和分辨率可选择由 AI 决定；参数按接口与型号显示。新人物自动立绘默认开启，自动 CG 默认关闭。图片在正文保存、人物资料确认后独立生成，失败可单独重试。操作及各模型参数见 [插画与故事图册](docs/USAGE.md#插画与故事图册)。

模型资料可能遗漏或误判，需通过原文出处核对。正文输出、手工修正、请求诊断、摘要压缩与生成过程的详细说明见 [使用指南](docs/USAGE.md)。

## 数据与备份

- 默认数据保存在 `data/`，不进入 Git。供应商密钥在服务端加密，页面仅显示是否已保存。
- 完整作品导出为 `.ai-novel.json.gz`，包含原文件、正文、故事线、历史资料、图片及其剧情关联、模型输出、任务进度和正文草稿；恢复时建立独立作品。正文也可单独导出 TXT。
- 作品备份包含作者秘密和请求素材，不包含登录凭据、供应商密钥或全局提示词设置。提示词预设可以独立导入导出。
- 迁移整个服务时，**停止服务后备份完整数据目录或 Docker 卷**，保留 `.encryption-key`，否则无法解密已保存的模型密钥。
- 删除作品无法撤销，需要保留时先备份。确认后会清理该作品的原文、正文、全部故事线、历史资料、任务和模型输出。

文件大小、恢复边界及删除中断处理见 [使用指南的备份说明](docs/USAGE.md#数据与备份)。

## 开发与文档维护

```sh
npm run typecheck
npm test
npm run build
npm run test:e2e
```

`test:e2e` 会先构建，默认使用系统 Microsoft Edge。测试服务使用独立临时数据目录与本地模拟模型，不调用真实供应商；没有 Edge 时需安装或调整 [Playwright 配置](playwright.config.ts)。历史测试结果见验收记录，不能替代改动后的相关验证。

- [AGENTS.md](AGENTS.md)：项目提示词与长期协作约束。
- [PROJECT-STATUS.md](PROJECT-STATUS.md)：当前能力、限制、最近改动和验证情况；**每次修改完成后、提交前同步更新**。
- [使用指南](docs/USAGE.md)：创作流程、模型与提示词设置、手工修正及备份。
- [API 契约](docs/API-CONTRACT.md)：接口与数据行为。
- [提取流程](docs/EXTRACTION.md)：证据、资料归并与版本规则。
- [模型连接排查](docs/MODEL-CONNECTIONS.md)：实际请求、参数及服务错误排查。
- [验收记录](docs/VALIDATION.md)：按日期保存程序、浏览器、真实接口与部署验证证据。

代码位于 `client/`、`server/` 和 `shared/`，验证位于 `tests/`。开始开发先阅读协作约定与项目状态；结束时执行相关验证，更新受影响的说明与状态，再创建本地提交。
