# 自定义工具与技能

在“设置 → 工具与技能”管理。配置对当前服务的所有作品生效，用于正文写作与 RPG 穿越体验。三个分页之间、与其他设置分类之间切换都会保留草稿，点击“保存工具与技能”统一保存这一类配置；模型设置仍用原来的“保存设置”。未保存就返回作品会提示放弃确认。

新脚本、新 MCP 服务和导入的技能默认停用。检查内容，勾选“启用”并保存后，之后发起的写作任务才能使用。可以在写作要求里明确要求某个工具或技能，但实际是否调用仍取决于模型。开启生成过程显示可查看真实的加载、参数、结果与错误；阅读视图只隐藏过程。

## 如何渐进式披露

1. 第一轮只提供已启用项目的 ID、名称与最多 160 字符的简介。最多先列 40 项，剩余项目可搜索，每页 20 项。不会发送脚本源码、自定义工具的完整参数格式、技能正文或附件内容。
2. 模型需要使用时，调用 `load_extension`。工具返回完整说明和参数 JSON Schema；技能返回 `SKILL.md` 第一段与附件目录。加载本身不执行脚本，也不连接 MCP。
3. 工具通过 `run_extension` 执行，参数用 `argumentsJson` 传入完整 JSON 对象字符串，再由服务器按原工具的 Schema 校验。技能附件和较长正文通过 `read_skill_resource` 按路径读取，每次最多 16000 字符，返回下一段位置。

没加载就执行会被拒绝。正文提示词预览使用与真实请求相同的已保存目录与入口；后续加载内容体现在各轮请求诊断中。现有故事资料检索、图片与玩家选择工具继续使用原约定。

RPG 断点保存已加载条目的内容指纹。续接时配置没变，可以继续使用；条目被修改、停用或删除时不会执行旧任务中的调用。保存扩展配置会取消正在执行的扩展工具；请在工具空闲时修改。外部工具可能有副作用，取消、超时或失败不保证撤销已经发生的操作，也不会由程序自动重试。

## JavaScript 脚本

点击“添加脚本工具”，默认带字数统计示例。填写名称、用途与使用时机、参数格式和 JavaScript 代码。代码是一个可使用 `await` 的函数体，参数对象叫 `args`，用 `return` 返回可序列化为 JSON 的值。例如：

```js
const text = String(args.text ?? '');
return { characters: Array.from(text.replace(/\s/g, '')).length };
```

对应的参数 JSON Schema：

```json
{
  "type": "object",
  "properties": { "text": { "type": "string", "description": "需要统计的文字" } },
  "required": ["text"],
  "additionalProperties": false
}
```

保存后展开“测试脚本”，填写测试参数，点击“运行测试”。这会实际执行已保存代码；即使没有启用，作者仍可手动测试。返回值显示在结果区；`console.log` 用于进程诊断，不当作工具结果。可用动态 `import()` 引入 Node 内置模块。

脚本运行在服务器上，工作目录为 `DATA_DIR/extension-runtime`，以服务账号权限执行。独立子进程用于停止执行、限制内存和输出，**不是权限沙箱**。只添加可信代码；脚本可以按服务账号权限访问文件或网络。进程只继承基础运行环境，不自动继承应用密钥等环境变量。不要在脚本源码里硬编码凭据。

脚本默认超时 10000 毫秒，可配置 100–60000 毫秒，V8 堆限制为 64 MiB；参数和结果分别最多 64 KiB。超时、取消和输出超限会停止进程。错误会留在工具过程里，程序不自动重跑。

## MCP 服务

支持两种连接方式，与 [MCP TypeScript SDK 的客户端传输方式](https://ts.sdk.modelcontextprotocol.io/client.html) 对应：

- **远程 Streamable HTTP**：填写完整 MCP 接口地址，例如 `https://example.com/mcp`。需要鉴权时，在“请求头 JSON”填写 `{"Authorization":"Bearer 你的令牌"}`。当前不提供 OAuth 登录，也不支持旧版独立 SSE 端点。
- **本地 stdio**：填写服务器上的可执行命令，例如 `node`，参数为字符串数组，例如 `["/opt/my-mcp/server.mjs"]`。使用需要的环境变量 JSON；应用不会替你安装程序或依赖。工作目录同样为 `DATA_DIR/extension-runtime`，脚本及资源路径建议使用绝对路径。Docker 中的命令、依赖和路径必须在容器内可用。

先保存，再点击“连接并发现工具”。这会启动本地进程或连接远程端点，完成初始化并读取分页工具目录；不会调用具体工具。发现完成后可以按名称展开查看说明和参数。模型以后只在实际调用时连接服务，每次操作结束关闭连接。

当前每次操作独立建立连接，不保留跨调用的 MCP 会话状态。适合查询、搜索等独立请求；需要连续维护浏览器页面或执行环境的有状态服务不在本次支持范围内。

凭据加密保存，页面重新打开只显示“已保存”，不回显内容。环境变量和请求头分别以空对象保留原值，填写非空对象会替换对应整组；勾选清除会移除两组凭据。更改地址、命令、参数或连接方式后不沿用旧凭据，工具目录也会清空，须重新连接。修改凭据同样需要重新发现目录。

过程与结果会屏蔽 Authorization、Cookie，以及名称包含 KEY／TOKEN／SECRET／PASSWORD／CREDENTIAL 的凭据值。普通端口、运行模式等环境值不当作密钥替换。不要让工具回传使用其他命名方式保存的凭据或自行读取的秘密文件。

HTTP 沿用 [出站来源规则](DEPLOYMENT.md)：生产默认 HTTPS 公网，私网或 HTTP 端点须加入服务器的 `OUTBOUND_ALLOWED_ORIGINS`。如果已设置名单，须同时列出所有需要的模型服务和 MCP 来源。拒绝 URL 内凭据、重定向和已知元数据地址。本地 stdio 程序自行发起的网络请求不经过此 HTTP 规则。

连接及一次调用使用同一个总时限，默认 30 秒，最多 60 秒。单个服务最多 200 个工具，目录分页最多 20 页，原始响应最多 2 MiB，送回模型的单次结果最多 64 KiB。结果超限会明确报错，不伪造完整结果。当前主要适用于返回小型文本或 JSON 的工具，不把图片、音频结果直接接入作品图册。

## 导入技能

支持单个 UTF-8 `SKILL.md`，或包含一个技能及附件的 ZIP。ZIP 可直接包含 `SKILL.md`，也可在一个上层目录中包含它；所有附件必须位于同一技能目录，不能包含绝对路径或 `..`。不会把附件解压成服务器可执行文件。

技能采用 [Agent Skills 规范](https://agentskills.io/specification) 的 YAML 元信息和 Markdown 正文。例如：

```markdown
---
name: scene-continuity
description: 续写或切换场景前，核对时间、地点和人物动作是否连贯。
---
先核对当前章节结尾，再核对新段落的时间、地点与人物。
有疑点时查询故事资料，不自行补造已有事实。
需要更细的清单时读取 references/checklist.md。
```

`name` 最多 64 字符，使用小写英文、数字及单个连字符；`description` 非空，最多 1024 字符。名称与简介在保存时从 YAML 重新解析。其他元信息保留在文件里，不自动改变工具权限。

导入后先进入未保存草稿且停用，检查正文与附件后再启用、保存。同名技能不会覆盖原技能，会提示重名。需要更新时可以直接编辑原技能的 `SKILL.md`；若要替换整个包，先在草稿里移除旧技能，再导入新包，最后保存。

包内的 `scripts/`、`references/`、`assets/` 等附件完整保留，模型按需读取文本；二进制附件保留但当前不能通过模型工具查看。技能中的脚本和安装命令不会自动执行，需要使用时由作者另行配置受信任的脚本工具或 MCP。当前不提供 Python／Shell 技能脚本的自动运行环境。

## 容量、备份与验证范围

最多保存 50 个脚本、20 个 MCP 服务、100 个技能，整份配置最多 8 MiB。技能上传文件和每个技能展开后分别最多 2 MiB；每个技能最多 200 个文件，单文件最多 512 KiB。工具参数 Schema 最多 32 KiB，支持默认 Draft 7 和明确声明的 Draft 2020-12，不加载外部引用；`format` 注解不作强制格式校验。同一服务最多同时执行 4 个扩展操作。

配置与模型设置分别保存，带版本检查；其他页面已经修改时，本次保存会拒绝并保留页面草稿，避免覆盖。全部配置加密存入应用数据库；完整停机数据目录备份会保留，迁移必须同时保留 `.encryption-key`。单作品备份不包含全局脚本、MCP 凭据和技能包，但生成诊断及 RPG 历史可能包含当时已经加载的说明和结果。

本地验收使用临时 SQLite、真实 Node 子进程、本地 MCP 测试服务及模拟模型请求。真实模型是否善于选择工具、第三方 MCP 的实际兼容性、远程 OAuth、Linux／Docker／NAS 运行与目标部署均未由这些测试证明。具体执行记录见 [验收记录](VALIDATION.md)。
