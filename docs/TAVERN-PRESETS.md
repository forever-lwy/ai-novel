# 酒馆预设原版结构移植与任务 v3

通用内置仅保留通用综合中性版，任务保留原始默认和四任务 v3；最早的 Dramatron 移植框架也不再内置。四份原版结构移植预设改为独立 JSON，不在应用中自动注册，运行包也不包含它们的提示词文本。

## 使用

推荐在“设置 → 提示词编排 → 通用预设”选择内置的 **通用综合 · 中性叙事**，再为四类任务分别选择 **v3 · 原版框架适配** 并保存。需要原版结构时，从[可选文件目录](../presets/README.md)取得对应 JSON，点击页面顶部“导入预设或任务提示词”，确认名称后保存。任务可以跟随当前通用预设、绑定另一份通用预设，或独立使用。

| 预设 | 保留的主要结构 | 默认结果工具 |
| --- | --- | --- |
| Dramatron 3.1 · 原版结构 | 原身份、CLEAR、原长文本、宏变量、视觉小说文风、三段输出及尾部引导 | `kemini_complete_reply(content)` |
| v0.8 · 原版结构 | 特图身份、原角色与文风规则、变量串联、draft、脚本文本库 | `output_everything_here(content)` |
| Reborn 2.3 · 原版结构 | 双模型设定、原版衔接对话、猫神人格、文风、SPreset 伪对话重排 | `game_content(content)` |
| Linux 1.3 · 原版结构 | 原终端框架、作者与文风规则、调度消息链、完整规范归档到工具说明 | `dispatch_stream_payload(display_stream)` |
| 通用综合 · 中性叙事 | 虚构文本边界、直接完整交付、工具归档与真实工具并用；文风由作者及前文决定 | `emit_complete_text(content)` |

更希望延续自己的写作风格时，使用中性综合版；需要比较某份参考预设的原有表现时，使用对应“原版结构”。此处“原版结构”表示保留文本及关键处理流程，不表示已经证明与酒馆具有相同通过率。

“工具防截断”可开关；“结果工具方式”可选旧分层工具、原生结果工具或归档结果工具。Reborn 默认启用“原版伪对话重排”，也能改回保持原消息。全部变化都能在最终预览中检查，保存后生效。

## 文件交换与旧目录清理

顶部“导出当前提示词预设”适用于通用预设和四类任务。任务导出附带实际搭配的通用预设，导入会重新分配预设和消息块 ID、允许改名，并将该任务绑定到新导入的通用副本；其他任务选择保留。旧 v1 任务文件继续按独立任务导入。支持选择文件或在底部粘贴 JSON，取消或校验失败不会修改当前编辑。

“导出全部提示词”保留所有预设、完整开关、绑定与当前选择，不含供应商和密钥。整套导入会先展示各类数量并确认替换当前提示词编辑，再由“保存设置”写入数据库。文件中的旧作者版本也会保留，不触发默认目录清理。

目录清理版本 2 在上一版基础上，把最早的三种 Dramatron 框架也纳入退役范围，移除完全未改动的旧 Dramatron／v0.8／Reborn、任务 v2 和四份原版结构内置项；原始任务默认和中性版／v3 保留。任何文本、名称、开关等手动编辑、复制项及被任务显式绑定的通用预设都会保留。被清理的通用选择优先回到中性版，至少保留一份；后续显式导入或整套恢复的作者内容不参与旧目录清理。主动移除已有修改版前，应先导出整套提示词留存，再删除旧项。设置仍在点击保存后写入数据库。

## 为什么需要修改请求流程

旧移植版主要保留了通用的虚构任务与直接交付说明，省略了原人格、衔接对话、部分宏与消息后处理；输出使用统一的 `emit_writing_response(prose, toolCalls)`。这种迁移适合无固定风格的框架，但不等于原始请求。提示词相同、承载工具或消息角色不同，也会得到不同的实际输入。

附件还包含浏览器脚本，不能把脚本效果当作提示词文本本身的能力：

- Dramatron 和 v0.8 的输出承载依赖发送前注入函数定义、返回后拆出字符串。新移植版实际注册结果工具，与资料查询、插画、`ask_user` 并列；输出函数只交付文字，不执行故事工具。四协议均使用自动工具选择，不替换作者保存的采样、思考或输出上限。
- Linux 脚本把整套预设、世界资料和聊天历史移入函数说明，真实消息只留下调度链。项目按相同机制归档本次任务与运行规则，并在完整预览的工具说明中展示。预设块上的 `carrierPart` 标记决定哪些是调度或工具说明；素材中出现同名字样不会被当成脚本指令。
- Reborn 的 SPreset 后处理独立于“聊天合并”开关：它拆开预设中的嵌入对话，合并相邻同角色片段，再构造 Gemini `Pass` 与 SoliUmbra 的开放伪 JSON 对话。项目静态重写了附件中实际启用的文本路径，只解释预设源块的角色标记，作品资料内的同名标记保持原文。预览与实际发送共用此处理。原生提取工具／Schema 优先使用任务原消息。

Reborn 重排预设与任务前缀后，项目补充的资料边界、玩家决定和实际提交接口仍以原消息角色附加；这部分不会降为伪对话。后续真实工具返回与签名也不会再次重排。

本项目不加载远程执行器，不执行附件 JavaScript、`eval`、浏览器 fetch 包装或任意正则。来源脚本只作静态阅读。原生响应、真实工具 ID、思考签名和用量仍由项目的协议实现处理；有真实工具时逐项返回结果，没有后续工具时直接结束，不增加结果确认请求。

## 文本、宏与任务适配

`presets/tavern-*.json` 保存实际移植文本、原消息角色、顺序和适用开关，仅在作者导入后成为当前实例的配置；不由应用源码导入，不依赖参考目录。`shared/neutral-preset.ts` 提供内置中性版。任务插槽放在原聊天历史入口，保留各任务块的真实角色。写作的人格、文风、剧情和分段要求只用于写作；提取、压缩、生图采用自身的事实边界与结果格式。

`feature=tavern` 只支持已用到的 `setvar/getvar`、注释、`trim`、`random`、骰子及固定用户／角色变量。随机选择和骰子按同一输入稳定展开，使预览与实际请求一致；不代表会复现酒馆每一次随机数。素材与自定义变量插入后不再次解释宏。不支持的宏明确报错，不执行脚本。

v0.8 的脚本原始用户文本库完整保留 7514 字符，放在任务入口前；原头部库保留首段 14460 字符，默认关闭。Dramatron 使用附件原长文本。填充可替换或关闭，计入上下文与用量；不会为适配上限暗中裁剪。附件导出不包含浏览器 localStorage，无法知道使用者在酒馆中实际选中的文本库、输入混淆或脚本开关。

全部提示词文本上限为 1000000 UTF-8 字节，JSON 文件读取上限为 8000000 字节，给转义字符和结构开销留出空间；导入后仍执行文本总量、20 份预设和每份 80 块的校验。旧配置可补入生图任务；中性版与 v3 在数量或容量不足时延后补入，不挤掉作者内容。

必要适配如下：

- 原固定 800／1000／1500 字要求改为本次作者目标；RPG 仍使用累计章字数和玩家决定，不让“抢话”或“不等待”代替玩家选择。
- 原自动小总结、行动选项、留言、状态栏、美化和 MVU 模块由项目已有功能承担，避免重复生成及写入正文。原文风与人格保留在对应移植版，中性版不包含这些风格文本。
- 不移植允许涉及未成年性内容的声明，不用宏更改人物年龄、意愿或已经确认的事实。
- 原脚本中的随机函数名改为稳定名称，便于完整预览、诊断与断点恢复；函数字段和原生调用机制保留。默认打开结果工具，区别于 v0.8 附件脚本的出厂关闭值；作者可在界面关闭。
- 不移植默认关闭的 Unicode／图片输入混淆、额外世界书匹配和未启用的推理预填路径。新预设保留在项目中可用的原选项，不提供任意 SillyTavern JSON 导入或通用脚本执行环境。

任务 v3 将“结果是什么”和“通过什么通道提交”分开：正文延续作者及通用预设文风；提取仍只接受编号片段证据；压缩只处理已发生剧情；生图优化组织一个具体画面、选择已有立绘及合法参数。生图优化保留原独立模型选择与补充要求，但现在通过同一编译、预览、预算及结果工具流程。实际图片接口只收到最终画面提示词和对应参数，不会收到伪终端、猫神对话或文字结果工具定义。

`textFilter=tavern` 逐片分离 `think/thinking/draft/think_nya~`、角色检查注释、终端前导、正文包装、摘要、状态和选项。辅助思考保存为作者过程，正文只保留故事；JSON 字符串内的标签与注释作为原文证据保留。过滤后没有正文或实际工具调用时明确失败，原始响应仍可检查。

## 验证边界

测试使用中性文本、隔离数据库及本地 HTTP／SSE 模拟，验证四协议最终请求、宏、消息重排、工具归档、输出解包、真实本地查询、暂停续接、截断留存和 JSON 格式配合。具体本次结果见 [验收记录](VALIDATION.md)。

未以真实供应商执行题材通过率对照。提示词无法保证上游接受特定内容，工具承载也不能突破硬输出上限或阻止网络断流；失败不会自动重新计费生成。相同文本比较时，还需核对模型、网关、采样参数、思考设置、输出上限和酒馆本地脚本状态。不能将本地模拟通过表述为已经恢复原版破限效果。
