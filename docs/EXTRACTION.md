## 当前流程

1. 保留已建立的章节与 5,500 字片段边界，未完成任务可沿用原进度。
2. 给提取模型当前编号片段及必要的已有名称提示，包括近期未具名人物；不混入未来预期规划或其他章节正文。伏笔索引只含正文中已埋下、尚未揭晓的条目。
3. 模型同时提取已发生的剧情摘要、人物、事件、状态及地理关系，引用只需标注段落编号；程序负责从当前片段取回精确依据。章节摘要包含因果、转折、人物变化和本章已揭晓的答案。
4. 本地补齐省略的可选字段，检查格式、引用、实体关联。原始响应、整理后的结果和人工修改分别留存。
5. 全部检查通过后，正文资料和任务进度一起提交；失败保留原文和输出，作者可以按条修正。

一次本地规范化不会再调用模型。正文、状态变化和实体关联的内容仍需模型理解，格式处理不能证明语义完全正确。

新建章节、导入和首次生成正文仍自动整理。手动编辑已有章节不会触发提取，也不会清空旧摘要、事实、关系或锁定内容；沿用原整理状态并保存新正文版本。引用只在本地重新定位，已失效引文解除但保留资料；这不代表资料已按新正文重新核实。作者需要更新资料时，显式选择“重新提取本章资料”，仍只处理目标章。

默认提取提示词按 Markdown 分为证据范围、摘要、人物归并、时间与可见性、关系、伏笔、输出检查和格式示例。明确要求只依据当前编号片段、每条事实只表达一个可核对结论、不凭名称索引补充事实；不能确定的身份或属性不补造。默认要求输出四个顶层字段及明确的时间、确定性、可见性；本地解析仍兼容下文所列的省略字段，不因此拒绝旧输出。完整最终消息及对应输出模式的规则可在“设置 → 提示词编排”预览。

默认提取将名称索引与当前编号原文放在同一条用户消息中，不加入模拟的助手确认语。三种输出模式共用这一单轮组织方式。未改动的旧默认提取预设自动升级；修改过的预设和副本保留原有消息结构。兼容网关出现空响应时可对照最终预览，手动停用无必要的确认语块，保留系统规则、原文和已有参数后再显式重试。单轮成功不代表所有模型或所有原文都会成功，真实对照范围见 [验收记录](VALIDATION.md)。

## 输出模式

`taskSettings.extraction.outputMode` 支持 `prompt`（默认提示词 JSON）、`structured`（接口 JSON Schema）和 `tool`（提交工具参数）。仅改变资料提交方式，导入、后台整理、版本检查、失败记录和人工修正继续走同一流程。

两种新模式共用 [提取输出结构](../shared/extraction-output.ts)，包含 `summary/entities/relations/foreshadows`。嵌套对象拒绝额外字段并列出全部必填字段，未知的 `nameStatus/isMain/attribute/dueChapter` 可以填 `null`；本地只将这四种可选字段的 `null` 视为未填写，其他必填字段的错误值仍拒绝。引用由当前片段的 `paragraph` 补齐精确原文，不要求模型重抄 `quote`。结构约束不能代替语义和证据校验。

- OpenAI Chat 使用 `response_format.json_schema`，Responses 使用 `text.format`，均开启 `strict`；规则依据 [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)。工具模式使用命名 `tool_choice` 并关闭并行调用，不要求上游具备严格结构化输出能力。
- Gemini 使用 `generationConfig.responseMimeType/responseJsonSchema`；工具参数使用 `parametersJsonSchema`，`functionCallingConfig` 设置 `ANY` 并限定提交工具。字段见 [Gemini generateContent](https://ai.google.dev/api/generate-content)。
- Claude 使用 `output_config.format`，保留已有 effort；工具模式使用 `auto`、关闭并行工具，并由提示词和本地校验要求提交，以保留思考设置和兼容禁止强制调用的型号。依据 [Claude 结构化输出](https://platform.claude.com/docs/en/build-with-claude/structured-outputs)及[工具选择规则](https://platform.claude.com/docs/en/agents-and-tools/tool-use/define-tools)。

工具模式只提供 `submit_extraction`，只接受一次同名调用并解析其 JSON 对象参数；没有执行函数，也没有工具结果回传或第二轮确认。预设中的 JSON 说明被明确解释为工具参数格式，不再叠加普通文本 JSON 规则。流式和非流式都保留实际请求、原始响应、参数文本、用量与诊断；截断、拒绝、错误调用或解析失败不会被当成完成。新结构计入发送前的上下文预算，不兼容时不自动降级或额外重发。

## 格式与证据规则

作者可在正文页“章节操作”中清除本章提取资料或单独重新提取。本章正文始终保留，旧摘要和非锁定提取结果先移除，锁定资料与事实保留；新请求只处理所选章，并沿用当前输出模式、提示词、原文校验及用量记录。其他章节的原有结果保留，早章重新整理时名称索引只取截至该章的资料，不借用后续称呼或线索。

旧章的清理和新结果同步到该章及之后的章末快照，后续已存在的属性状态仍按原文时间排序，重复提取不累积旧摘要和重复事实。旧版本不重写，回退可恢复旧资料。分段失败保留已完成的新片段，显式重试从失败片段继续；尚未配置模型或缺少历史快照时先拒绝。具体入口、范围与恢复方法见 [使用指南](USAGE.md#删除章节与资料单章重新提取)。

提取自动重试默认关闭，可在“设置 → 任务模型”设置额外请求次数和间隔。每个失败片段独立计数，保留每次响应与用量；已完成的片段和正文不重新生成。网络、超时、HTTP 5xx／408／429、格式或证据校验失败可按设置重试；配置、预算、其他 HTTP 4xx、存储错误、暂停、取消与版本变化会停止。次数耗尽后保留进度，支持手工修正或显式重试。服务重启不自动重复请求。完整操作见 [使用指南](USAGE.md#提取重试与摘要压缩)。

- 顶层必须有字符串 `summary` 和数组 `entities`，不能把空对象或服务错误当作成功提取。`relations`、`foreshadows` 可省略为空数组。
- 实体仍需类型、名称。可省略别名、描述和事实列表；事实需有具体内容及可定位证据，关系需有两端名称、标签及证据。
- 省略的时间、确定性采用 `unknown`、`inference`；事实与关系省略可见性仍采用 `secret`。实体省略可见性时，只要包含明确标为 `public` 且非 `future` 的事实，就从这些已公开事实判为 `public`，否则保留 `secret`；明确的实体秘密标记和错误值不被覆盖。不能因省略档案层标记，把明确公开的人物位置等事实一并改成秘密。
- 没有 `quote` 时按有效 `paragraph` 取回当前片段原文。长段拆成多个片段时，只使用模型本次看到的切片，不提前引用后半段。
- 旧引文存在时优先匹配原文；仅空白、引号差异可保守对齐，必须唯一定位。不会忽略字词差异、对错对象或任意挑选一处重复文字。
- 单个完整 JSON 代码块外不超过 512 字符的说明、代码围栏及字符串外的尾逗号可做有限格式处理；多个候选、结构截断、遗漏值仍报错，不凭空补数据。
- 关系或伏笔指向不存在、重名的实体时，集中展示关联问题。不能通过随意新建同名人物来掩盖问题。
- 同一批次先根据主名称与明确别名联系归并，再匹配历史资料。仅共享泛称、外貌相似、姓名包含或实体类型不同不会自动合并。明确的别名联系可归并旧重复条目，并重定向关系和伏笔关联；多个锁定身份或重名歧义需人工核对。归并继续保留引用、锁定与秘密可见性。
- 位置使用 `attribute: location`。明确的同类当前状态按原文章节和段落顺序更新，历史到达记录转为过去；回忆、未来目的地、推测及锁定冲突不会覆盖已经确认的位置。

## 剧情、伏笔与地图

`summary` 按片段顺序存入当前章节的剧情摘要，在剧情页按章展示，供续写使用。它记录已发生的剧情；预期规划功能已移除，旧规划仅保留在历史数据中。已揭晓或已放弃伏笔保留在历史记录中，默认界面及待处理上下文只显示未揭晓条目，模型的重复提及不会自动重新打开同名线索。

世界资料卡片固定高度，只预览部分内容，点击打开完整资料与出处。地图只展示地点之间的地理关系，明确方位可影响相对排布，未知方位只表示连接，不构造精确坐标或距离。人物当前位置在图外单独显示。摘要、伏笔状态与位置事实都属于故事版本，回退、修订或从旧章节分支时读取当时的快照。

阅读资料使用所选章节结尾的历史快照，人物、物品、名称／别名、身份归并、关系与当前位置一并恢复；不能从最新资料删除后续引用来推算过去，因为后续提取已经把旧位置改为“过去”，也可能更改名称或合并身份。快照须匹配当前故事线的完整正文前缀，继承的分支、回退与备份恢复保持同一规则。阅读接口在服务端进一步移除秘密、未来事实与越界引用，并从可见事实重建当前简介；过去事实保留供详情核对。正文目录仍完整供切章，阅读投影不写入故事版本，也不调用模型。作者视图保持完整当前状态。

旧版曾把省略的实体可见性统一补成秘密，并把该实体的公开事实和关系一同转为秘密。读档时依据同一版本祖先路径内已成功应用的提取结果、本地补字段记录、唯一实体名称及逐条一致的事实与引用，兼容恢复误隐藏的公开资料；没有证据、失败输出、其他故事线或错配引用不参与恢复。明确的秘密、未来事实、人工确认的秘密和锁定资料保留。旧快照及原始／归一化输出不被重写，完整备份保留这些依据，恢复作品后沿用同一兼容规则，不重新调用模型。

已有资料不会因升级自动重新调用模型。后续提取遇到明确的别名联系时可以归并旧重复条目；没有身份依据的旧资料仍需作者用“合并”确认，暂停任务与已保存进度保持原样。

## 手工修正

作者打开任务的“模型输出 / 手工修正”后，默认看到中文表单。按提示定位错误卡片，修改内容或选择原文段落；可以使用整段原文，也可以选中其中一部分作为证据。修改引用之前先核对事实本身，删除没有依据的错误条目。

“保存并校验应用”保存修改并执行本地检查。成功后任务完成或暂停，需继续整理后续片段时再手动继续。“重试”则会产生新的模型请求。原始响应始终只读，可下载；高级 JSON 仅作为完整结构与语法修复入口。

## 验证边界

程序及浏览器测试使用中性文本、本地模拟模型和独立数据库，覆盖简化结果一次通过、精确证据回填、含糊引用拒绝、人工修正、响应留存及不增加模型调用。它们不等于同一真实模型的成功率评测，也不证明资料语义正确率。

## 人物资料维护

人物提取使用 gender（性别）、bloodline（血统）、identity（身份）、能力与性格等资料属性，不把吃饭、赶路等普通行动逐条存入角色经历；普通行动归入章节剧情摘要，重大事件用 major_event。未知字段留空，不能编造。能力和性格可用 ability:archery、personality:courage 等稳定细分属性，后续更新同一属性，其他能力继续保留。

当前明确资料随章节、段落更新，旧状态保留为历史，人物简介从当前资料字段与重大事件汇总。nameStatus=placeholder 表示暂称；仅在明确的名称或别名身份桥下升级为 confirmed 真名，旧暂称移入 aliases，真名不再只挂在别名中。锁定实体及事实保留作者确认内容。isMain 用于主要人物识别；已有作者主次选择优先，提取不能自行覆盖。

正文生成与资料提取为不同任务。正文生成完成即可阅读、编辑或重新生成；后台提取仍按片段持久化，失败只重试提取。重新生成从目标章之前新建分支，取消旧后台任务后其迟到响应只能作为输出记录留存，不能覆盖任何故事资料。
