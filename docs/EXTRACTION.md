## 当前流程

1. 保留已建立的章节与 5,500 字片段边界，未完成任务可沿用原进度。
2. 给提取模型当前编号片段及必要的已有资料提示；不混入写作粗纲、未来细纲或其他章节正文。
3. 模型描述人物、事件、状态及关系，引用只需标注段落编号；程序负责从当前片段取回精确依据。
4. 本地补齐省略的可选字段，检查格式、引用、实体关联。原始响应、整理后的结果和人工修改分别留存。
5. 全部检查通过后，正文资料和任务进度一起提交；失败保留原文和输出，作者可以按条修正。

一次本地规范化不会再调用模型。正文、状态变化和实体关联的内容仍需模型理解，格式处理不能证明语义完全正确。

## 格式与证据规则

- 顶层必须有字符串 `summary` 和数组 `entities`，不能把空对象或服务错误当作成功提取。`relations`、`foreshadows` 可省略为空数组。
- 实体仍需类型、名称。可省略别名、描述和事实列表；事实需有具体内容及可定位证据，关系需有两端名称、标签及证据。
- 省略的时间、确定性、可见性采用 `unknown`、`inference`、`secret`，避免未经说明就当成当前、确定、公开的信息；明确提供的错误值不会擅自改成默认值。
- 没有 `quote` 时按有效 `paragraph` 取回当前片段原文。长段拆成多个片段时，只使用模型本次看到的切片，不提前引用后半段。
- 旧引文存在时优先匹配原文；仅空白、引号差异可保守对齐，必须唯一定位。不会忽略字词差异、对错对象或任意挑选一处重复文字。
- 单个完整 JSON 代码块外不超过 512 字符的说明、代码围栏及字符串外的尾逗号可做有限格式处理；多个候选、结构截断、遗漏值仍报错，不凭空补数据。
- 关系或伏笔指向不存在、重名的实体时，集中展示关联问题。不能通过随意新建同名人物来掩盖问题。

## 手工修正

作者打开任务的“模型输出 / 手工修正”后，默认看到中文表单。按提示定位错误卡片，修改内容或选择原文段落；可以使用整段原文，也可以选中其中一部分作为证据。修改引用之前先核对事实本身，删除没有依据的错误条目。

“保存并校验应用”保存修改并执行本地检查。成功后任务完成或暂停，需继续整理后续片段时再手动继续。“重试”则会产生新的模型请求。原始响应始终只读，可下载；高级 JSON 仅作为完整结构与语法修复入口。

## 验证边界

程序及浏览器测试使用中性文本、本地模拟模型和独立数据库，覆盖简化结果一次通过、精确证据回填、含糊引用拒绝、人工修正、响应留存及不增加模型调用。它们不等于同一真实模型的成功率评测，也不证明资料语义正确率。
